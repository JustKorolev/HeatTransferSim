# Thermal validation figures

Generated by [`docs/surf_report/make_validation_figures.py`](../../docs/surf_report/make_validation_figures.py).
Each figure ships as both `.png` (slides) and `.pdf` (vector, for the report).

```bash
python docs/surf_report/make_validation_figures.py
```

Add `--plot-only` to restyle from the cached series in `data/` without re-running
the solver.

## Solver configuration

All runs use the converged settings — 512 adaptive substeps, target ΔT 1e-3 K,
rtol 1e-11, CPU solver, direct graph build (no octree import). These make
discretisation, not time stepping, the dominant error term.

The two-block case overshoots its 0.05 K tolerance by 14% during the
mid-transient; both blocks land on the analytical equilibrium temperature, so
this is a transient-shape discrepancy across the contact conductance, not a
steady-state or energy-balance error.

## Notes

- **The prism figure uses a 60 s window, not the suite's 2 s default.** Copper's
  L²/α is ~86 s, so at 2 s only the probe nearest the fixed face has moved and
  the other three sit flat at their initial temperature. The extended run is the
  same experiment against the same 3 K tolerance (max error 0.96 K); the 2 s
  default is what `val_1_summary` reports.
- **Do not plot from `validation-assets/thermal_validation_results*.json`.** Those
  are stale exports from the GLB + octree import path, which lost 56% of the
  requested volume; the prism case there shows 53–82 K errors. The series under
  `data/` here are the authoritative converged runs.
